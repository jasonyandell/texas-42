**Version:** 0.1

**Status:** pre-freeze implementation rebrief; proposed adjudication, not authority  
**Target gate:** M3 explicit grade-4 perfect-recall-net parity  
**Parent authority:** GT1-A1..GT1-A17 and freeze 56  
**Proposed next freeze:** freeze 57, only after this rebrief and a separate binding
M3 contract survive adjudication

This rebrief is the explicit bridge required by the freeze-56 range close.  It
does not amend any existing ruling, receipt, manifest, or freeze.  In particular,
it does not silently promote the exploratory implementer's guide or any
pre-freeze audit computation into authority.

M3 is a correctness gate for one full perfect-recall information net on one
small, real, complete grade-4 carrier.  It has two independently typed valuation
arms over the same carrier: future trick differential and the binary event that
the declaring team makes its P30 contract.  It is deliberately large enough to
exercise every future focal action face, hidden-particle filtering, exact field
mass, pooling by full observation, backward policy evaluation, and Metal
expansion/reduction.  It is deliberately not a trick-1 solve, a representation
growth verdict, or a player.

The governing discipline remains exact arithmetic, CPU/reference semantics as
authority, full observation rather than a descriptor, no strategy fusion, no
silent truncation, and no partial result.  Any unresolved item explicitly named
below blocks freeze 57; an implementer may not choose it by convenience after
observing a result.

## 2. Exact M3 scope and the two mandatory arms

M3 contains exactly eight official tasks, in this order:

```text
M3A h8 root 21    future T1 trick differential; H parity plus typed C control
M3A h8 root 31    future T1 trick differential; H parity plus typed C control
M3A h8 root 33    future T1 trick differential; H parity plus typed C control
M3A h8 root 55    future T1 trick differential; H parity plus typed C control

M3B h8 root 21    declaring T1 makes P30; H parity plus typed C control
M3B h8 root 31    declaring T1 makes P30; H parity plus typed C control
M3B h8 root 33    declaring T1 makes P30; H parity plus typed C control
M3B h8 root 55    declaring T1 makes P30; H parity plus typed C control
```

The task list is carrier-selected, not result-selected: all four legal roots are
present, in ascending domino-index order, whatever their values or ties.  Each
task conditions on its named physical root action and builds every later focal
action face.  A root is never replaced by only the action presently believed
best.

Each official task contains one lawful-H subrun and one separately typed
world-split-C negative-control subrun.  The two arms have different valuation
types and independent CPU authorities.
They may share unchanged `walt-core` game rules and the canonical input carrier,
but they do not share a value cache, policy cache, partial net, objective state,
or receipt task record.  The official gate constructs each root/arm task from
fresh state.  Because neither arm prunes on objective decidedness, their net
topologies must agree root by root; that equality is a receipt, not permission to
reuse one arm's values in the other.

M3 excludes:

- the freeze-51 h2/h9 synthetic void-free stress partitions;
- a trick-1 coordinate, opening-root value, lead selection, or K-OPEN4+ result;
- a persistent compressed basis, rank claim, growth verdict, or crossover claim;
- gluing, Scheme/Fix, a plan lower witness, or a controller;
- timing as a content gate, production tuning, and player integration;
- any inference from a grade-4 carrier to the opening.

The freeze-51 units remain immutable prior objects.  Their roughly 82.8-million
h2 and 517.6-million h9 scalar partitions per root make them plausible optional
M4 growth/stress carriers only after M3 passes and after their own explicit
rebrief.  They are not mandatory M3 work and cannot rescue or defeat M3.

The only success sentence admitted by this gate is:

```text
M3 PERFECT-RECALL NET PARITY COMPLETE under freeze 57
```

It may be issued only after freeze 57 exists and every conjunction in this
document's eventual binding contract passes.  It makes no trick-1, performance,

`HistoricalVoidFeasibilityOnlyV1`, and `UniformRandomLegalV1`.  The declared

## 4. M3A: future trick-differential authority and strict C control

M3A values the four remaining tricks only.  A trick won by T1 contributes `+1`;
a trick won by T0 contributes `-1`.  Thus a terminal with `k` future T1 tricks
has value `2*k - 4`, for `k in 0..4`.  Count points on dominoes do not enter this
arm.

The independent CPU H authority is the existing `ScalarHidden`, freshly invoked
on the complete 1,200-world carrier with `viewer=S1`, `focal=T1`,
`ScalarValuation::trick_only()`, the same fixed-uniform-legal field, and each
fixed root.  Its existing information grouping remains an oracle; M3 production
code may not call into its recursion, memo table, key type, or aggregation code.
The two paths may share only the frozen game rules and canonical carrier input.

For every root, separately typed CPU and GPU revealed-continuation computations
evaluate each world as a one-world bag under the same stochastic field and
average the results.  This is treatment C: the root remains common, but all
later focal choices may depend on the hidden world.
`M3WorldRevealedKeyV1` carries the world ordinal explicitly and cannot be
constructed where an H key is required.  CPU/GPU C net, mass, face, policy and
root-value parity is mandatory as a negative-control subrun of each M3A task.
Treatment C is never an H result, even if a numerical equality happens on a
different carrier.

On this carrier the official run requires strict `Q^C(a) > Q^H(a)` for all four
roots.  That is a deliberate negative control for accidental world splitting.
Failure of strictness is stop-and-report; the carrier is not changed after the
fact.

A pre-freeze audit observed the following values.  They explain the carrier
choice but are **not frozen expected outputs and may not be hard-coded**.  The
gate earns them again through the independently implemented CPU and GPU paths:

The acceptance object is independent parity plus strict inequality, not a

## 5. M3B: independently written P30 loss automaton

M3B's terminal utility is one exactly when declaring T1 makes P30 and zero
otherwise.  It starts with T0's remaining allowance `11`.  Whenever T0 wins a
completed future trick, subtract exactly

```text
1 + the count value of the four tiles in that trick.
```

The implementation tracks exact future T0 spend in `0..34`, equivalently the
signed remaining allowance `11 - spend` in `-23..11`, without saturation.  It
continues through the complete four-trick horizon even after make or set has
become inevitable.  Consequently M3B emits the same future action faces as M3A,
including faces after the provisional set threshold has been crossed.  No
early-set or early-make shortcut may hide a frontier in this gate.  At terminal,
T1 makes exactly when future T0 spend is at most 11.

The CPU H authority for M3B is a new, independently written pooled scalar
loss-automaton oracle.  It enumerates all 1,200 worlds for each fixed root,
branches each field seat uniformly over its own legal set, groups the viewer by
the complete actor-attributed observation, chooses one viewer action per group,
and returns an exact make probability under the carried posterior weights of
section 3, never a fresh uniform weighting of survivors.  It shares only `walt-core` legality,
winner/count rules and the canonical carrier.  It does not reuse the production
net builder, GPU buffers, host sorter, reduction code, objective evaluator, or
policy table.

An independently written one-world version supplies M3B's separately typed CPU
C control, and the production GPU runs the same separately typed world-split
negative-control mode.  CPU/GPU C net, mass, face, policy and root-value parity
is required, but M3B does not predeclare a strict C-H gap.  M3A supplies the
mandatory strict world-split controls.  No M3B output is inferred from the M3A
trick distribution; the binary automaton is evaluated directly so that contract
bookkeeping is actually exercised.

## 6. Scoped task frame and exact full-key bytes

Every comparison occurs inside an immutable `M3TaskFrameV1`.  The frame contains
the freeze/build identities, arm, treatment H/C, valuation, carrier and support digests,
declaration/contract/teams, fixed physical root, field law, arithmetic identity,
codec version, ABI version, cap profile and canonical order.  Arm, objective and
task identity are outside the information key.  A key from one frame is never
looked up in a table belonging to another frame.

This scoping is essential: v0.3 requires the public contract/declaration
objective state to be part of the observation object, while the M3 codec avoids
repeating frame constants in every key.  The equivalence proved and tested is
therefore

```text
(same complete task frame and equal key bytes)
    iff
(same perfect-recall focal observation for that task).
```

Raw key bytes alone make no cross-task claim.

`M3PerfectRecallKeyV1` has exactly this canonical byte encoding:

```text
offset  width  field
0       1      codec version = 1
1       1      focal seat, canonical Seat index
2       4      current focal-hand bitset, little-endian u32
6       1      public-record length n
7       2*n    n chronological pairs (actor Seat index, Domino index)
```

Only low 28 hand bits are legal.  `n <= 28`; actors, dominoes and record length
are range-checked; no tile may be replayed twice.  The record is the complete
actor-attributed public play record from the start of this hand: the twelve-play
base prefix, the fixed root, and every later observed play.  The root action is
therefore the thirteenth pair and cannot disappear through same-context reuse.

Leader, seat to act, current trick prefix, completed winners and points, current
hand size, remaining pool, remaining loss allowance and terminal status are
replayed from the task frame and record.  They are validated against the
production state but not redundantly encoded.  The explicit focal-hand field is
also replay-validated.  Any record that cannot be produced by legal replay in
the named frame is malformed.

There is no descriptor, observation hash, cell identity, hidden-holder field,
hidden-world value, proof datum, candidate/program field, or tie-broken
clairvoyant action in these bytes.  A hash may prefilter candidates in memory,
but equality always performs a length-and-byte comparison of the complete key.
The constant-hash negative test must produce the identical net and receipt.

`M3WorldRevealedKeyV1` is the pair `(support world ordinal,
M3PerfectRecallKeyV1)`, with the ordinal encoded as a checked little-endian
`u32` less than 1,200 before the complete H-key bytes.  Its equality biconditional
is equality of the revealed world and the complete lawful public observation.
The H and C key types have disjoint constructors and persistence tags.  The
world ordinal never replaces the observation bytes: one revealed world still
admits many stochastic public histories and therefore many perfect-recall
states.

`InfoStateId` is a process-local handle assigned only after full-byte grouping.
It is neither semantic nor stable and is never persisted.  Persisted task
evidence carries complete key bytes in canonical order, or a complete
content-addressed section whose verifier reconstructs and compares every byte;
an `InfoStateId` alone is never evidence.

## 8. Full action-conditioned net and forced final frontier

The net is generated in focal decision epochs.  For every pooled focal key:

1. validate and retain its complete legal action set in ascending domino index;
2. emit one action branch for **every** legal action;
3. expand non-focal legal plays until the next focal decision or terminal;
4. construct the complete child key and merge only byte-equal children;
5. retain exact edge mass and objective contribution;
6. after the full horizon exists, evaluate action rows backward and retain the
   complete argmax face.

The focal seat's final one-tile decision is a real information frontier.  It is
emitted, counted, encoded, sorted, replay-checked, mass-checked and policy-checked
with its singleton legal face.  A singleton fast path may avoid evaluating a
comparison, but it may not skip the node or its receipts.

No only-best-action traversal, tie-broken face, sampled face, or
world-conditioned action is accepted.  A canonical least-domino member may be
derived after the complete argmax face is known, solely to make one deterministic
policy byte stream; the receipt retains and compares the full face as the
mathematical object.

For a complete information state `I`, let `L(I)` be its complete legal face,
let `T_I(a)` be the root-scale unnormalized terminal contribution reached after
action `a` before another focal state, and let `J` range over every complete
byte-equal child state reached after that action.  The binding recurrence is

```text
A_I(a) = T_I(a) + sum_J V_J
V_I    = max_(a in L(I)) A_I(a).
```

Every particle and physical slab contributing to one byte-equal `J` is summed
before `V_J` is compared or any maximum is taken.  At the root sentinel, terminal
contributions and the `V_I` values of every first frontier are summed in the
same way.  Backward induction over the strictly extending record proves that
this recurrence equals the maximum over the free product of lawful policies
mapping each H key to one action in `L(I)`.  The production path must also choose
one canonical member of every complete argmax face and reprice that fixed policy
through an independent no-maximization walk to the identical root value.

Every child record strictly extends its parent's complete public record through
one focal action and zero or more later public field plays.  Therefore a child
full key has a unique parent key and focal action.  The first frontier uses a
distinct root sentinel, and terminal records retain the same unique preceding
parent/action reconstruction.  The statement holds separately for the
world-prefixed C key.  This perfect-recall unique-parent property licenses
parent-local streaming across different parents: equal child keys cannot cross
parent/action domains because their bytes would contain unequal parent prefixes.
It must be proved for the abstract codec and checked by replay for every emitted
child.

Unique parent does **not** license slab-local sealing.  One `(parent, action)`
emission may span multiple physical `2^19` slabs.  Every slab becomes a sorted
run, and a deterministic full-byte run merge must consume every run and every
source ordinal for that parent/action before a key is sealed or any maximum is
taken.

The host sorts and nets each complete parent/action emission by **complete key
bytes**, then by support source ordinal, using the run merge just specified when
more than one physical slab is needed.  Hashes may form buckets only; every
bucket performs a full comparison.  No cross-parent global sort is required
once the unique-parent receipt holds.  Canonical persisted order is:

```text
(arm/task ordinal, physical root Domino index, treatment ordinal H then C,
 full key bytes lexicographically, support source ordinal)
```

The source ordinal is the contiguous rank of the initial world in the filtered
freeze-7/23 support stream.  It is scheduling metadata, not part of the H key or
policy observation.  For one fixed full record a starting world has at most one
particle, so this ordinal also gives a stable within-key particle order.

## 9. Exact mass representation

After the fixed root there are twelve non-focal decisions: three in the current
trick and three in each of the three later tricks.  Since every legal-set size is
in `1..7` and divides 420, both arms use the common exact terminal scale

```text
M3_TERMINAL_SCALE_V1 = 1200 * 420^12.
```

The intermediate mass frame is part of the type.  After exactly `r` future field
moves, numerator `n` denotes

```text
n / (1200 * 420^r).
```

A field transition with legal degree `d` produces
`(n * (420/d), r+1)`.  The exponent is replay-derived and checked; frames with
different exponents never add until a checked horizon lift makes them equal.
Focal actions copy the complete conditional mass independently into every
counterfactual action row and do not act as chance splits.  Conservation is
therefore asserted separately inside each action row; summing the duplicated
mass across alternative focal actions is forbidden.  Treatment C retains the
same global `1/1200` root averaging while streaming one world at a time.  Future
posterior weights are never reset to uniform at an information state.

All official paths run the full horizon, so no early-terminal padding rule is
needed.  Every action row independently asserts child mass equals parent mass at
the appropriate exponent; every epoch, root and terminal distribution asserts
complete conservation.

Mass is `U256MassV1`, eight little-endian `u32` limbs, with the already frozen
checked operations.  M3A accumulates five nonnegative terminal mass buckets for
`k=0..4` T1 tricks and derives the signed differential by ordered subtraction of
positive and negative contributions.  It also checks the exact bridge
`differential = 2*count - 4`.  M3B accumulates disjoint make/set terminal mass
buckets and asserts their sum is the root mass.  Objective values are reduced
fractions only after exact numerator checks.

Particle multiplicity, probability mass, support count, state count, legal
degree, loss allowance, trick count and utility are distinct typed fields.  None
is silently substituted for another.  No floating-point type, literal,
operation, timing-derived coefficient, approximate comparison, tolerance, or
stochastic reduction enters the proof path.

## 10. Metal/host split and M3 work unit

One `M3PerfectRecallTaskV1` is one complete `(arm, h8, physical root)` task.  It
starts from a freshly reconstructed 1,200-world support and ends only after the
complete net, backward evaluation, controls and task digest succeed.

Metal performs actual semantic work:

- fixed-slot field expansion and legal-set generation;
- state transition and hand removal;
- complete-trick winner and count resolution;
- exact `U256MassV1` multiplication/addition and deterministic range reductions;
- terminal trick-bucket or make/set-bucket accumulation.

The host performs:

- task/frame construction and public replay;
- full key-byte construction and validation;
- full-key local sort, byte comparison and net assignment;
- action-face orchestration and backward dependency order;
- receipt framing and independent CPU comparison.

The host may not solve values on the CPU and upload answers for the Metal path.
Metal output remains untrusted until command completion, guard checks, replay,
mass conservation, and cell-for-cell CPU parity pass.

Each field-expansion input owns seven fixed output slots, ordered by ascending
domino index.  Slot `7*i+j` is either the `j`th legal child or canonical EMPTY;
all unused slots remain poisoned EMPTY and all guards remain unchanged.  Each
logical output has one writer.  Exact scalar-word layouts, offsets, alignment,
entry points, buffer indices and EMPTY/error encodings must be enumerated in the
binding M3 contract before freeze.  Native enums, bools, pointers, padding,
`usize`, and vector-layout assumptions do not enter persisted or shared ABI
bytes.

The existing M2 Metal binding/compiler identity is inherited only where its
frozen ABI actually applies.  Every new buffer layout, kernel entry point,
library digest, completion frame and unsafe call site is M3-specific and must be
audited and frozen.  Reusing the same generic checked host-to-buffer,
buffer-to-host and bind-buffer unsafe operation classes is permitted; adding an
unsafe operation class requires explicit adjudication.

## 11. Exact content caps and liveness limits

The proposed M3 h8 content caps are:

```text
M3_PHYSICAL_INPUT_SLAB_CAP_V1         2^19 =     524,288 records
M3_FIXED_OUTPUT_SLOT_CAP_V1         7*2^19 =   3,670,016 records/command
M3_H_FULL_KEY_STATE_CAP_V1             2^23 =   8,388,608 focal keys/root/arm
M3_PARTICLE_NODE_VISIT_CAP_V1          2^26 =      67,108,864 visits/root/arm/treatment
```

After a fixed first-frontier action, each hidden seat has at most three tiles, so
its remaining ordered plays number at most `3! = 6`.  A fixed focal continuation
therefore has at most `6^3 = 216` arrivals per world and
`1,200 * 216 = 259,200 < 2^18` total arrivals.  Covering both orders of the
focal seat's final two tiles doubles the complete all-actions `(I,b)` batch bound
to `1,200 * 432 = 518,400 < 2^19`.  M3 uses the latter cap so complete action
coverage does not depend on an unadjudicated action-slicing optimization.  This
is a physical dispatch/slab cap, not a claim that the root-to-first-frontier
emission or an arbitrary multi-parent batch fits one slab.  Any larger complete
semantic emission is split into canonical sorted runs below this cap and sealed
only by the all-run merge of section 8.  The binding contract must prove the
stated remaining-tile premise for the exact post-first-frontier work-unit cut and
assert the bound before allocation.

The logical output buffer has exactly seven slots per admitted input.  Its
physical allocation has exactly `3,670,018` records: one leading guard, the
`3,670,016` logical slots, and one trailing guard.  Guards are not part of the
content cap and both must remain unchanged.

A pre-freeze audit observed H full-key focal-state counts `4,090,174`, `3,286,841`,
`3,549,831`, and `5,067,710` for roots 21, 31, 33, and 55 respectively, total
`15,994,556`.  These are feasibility observations, not hard-coded expected
results.  The two independent implementations must recompute and agree on the
counts; the fixed root-local H cap is result-independent and exceeds the
observed maximum.  Treatment C is streamed one revealed world at a time; it does
not allocate one aggregate world-salted partition.  Its complete emitted work
is bounded by the separately typed particle-node visit cap, and every per-world
key/face/policy stream is still digested and compared.

The visit unit is one `(particle, semantic node)` actually computed, charged
before descent, exactly the existing unmemoized `tree-v0` unit.  Pre-freeze
tree-v0 traversals consumed respectively `32,702,041`, `27,127,740`,
`29,793,720`, and `37,693,228` visits at roots 21, 31, 33, and 55; the existing H
and revealed-C traversals agree on that count.  These readings justify but do not
define the result-independent `2^26` cap.  M3A and M3B have identical topology
because objective pruning is forbidden, so the cap applies independently to
each root/arm/treatment subrun.  CPU-oracle work and production CPU/GPU work are
charged separately, never combined or allowed to replenish one another.

Freeze 57 must prove that the M3 generator uses exactly this visit unit.  If the
new net's natural emitted-record unit differs, it receives a separately named
and derived cap; an emitted record may not be relabeled a tree-v0 visit merely to
inherit `2^26`.  No cap may be raised after a capped result is seen without new
adjudication.

Host and Metal live-byte caps cannot yet be integers because the M3 record widths
and buffer layouts are not yet frozen.  Freeze 57 is blocked until the binding
contract enumerates those widths and derives exact live-byte caps, including
input, seven-slot output, reduction scratch, key/sort records, poison and guards.
The derived total must be checked against actual device limits before allocation.
This open item is not papered over with a percentage of unified memory.

The liveness limits are separate from content:

```text
child committed Metal command        600,000 ms
parent committed-command watchdog    605,000 ms
child complete root/arm task       14,400,000 ms
parent root/arm watchdog           14,405,000 ms
CPU-phase liveness outside task       600,000 ms
```

They detect a dead child, driver, or orchestration failure.  They never truncate
a carrier, accept a partial epoch, change a content cap, or become a performance
claim.  Only native command completion with no error permits a buffer read.  A
timeout, crash, malformed progress frame, cap hit, arithmetic error, guard write,
or parity mismatch rejects the entire task.  The command interval begins only
after a flushed COMMITTED frame; the task interval begins at TASK_BEGIN and is
absolute, never extended by progress.  Polling is monotonic and at most 10 ms.
The binding frame language must make the child's timeout terminal precede exit
124 and give the parent enough fixed slack to receive it without a race.

## 12. CPU/GPU parity receipts

For every one of the eight tasks, the canonical success record includes and
asserts:

1. parent freeze/build/manifest identities and the full semantic task digest;
2. exact public-prefix replay, objective facts, void sets, support count and
   support-stream digest;
3. fixed physical root and full legal root list;
4. per-epoch and total emitted-record, full-key, singleton-frontier, action-edge,
   terminal and particle-visit counts;
5. byte equality of the canonical CPU and GPU full-key streams;
6. complete legal-action-face equality at every key;
7. edge-source, parent/action reconstruction and unique-parent equality;
8. exact per-edge, per-action, per-key, per-epoch and root mass equality;
9. terminal-bucket and objective-numerator equality;
10. complete argmax-face and canonical policy-byte equality at every focal key;
11. exact root-value equality and equality with the independent no-maximization
    repricing of the extracted canonical fixed policy;
12. high-water values strictly within every frozen content and byte cap;
13. all poison, tail and guard regions unchanged; and
14. no partial section, unknown key, duplicate source ordinal, or unconsumed
    record.

M3A additionally binds the fresh `ScalarHidden` output, the separately typed C
output and four strict `C > H` controls.  M3B additionally binds the independent
pooled loss-automaton output, loss-state transition census, make/set partition and
its separately typed one-world C output.

The receipt preserves complete faces.  A least-index policy stream without the
corresponding complete face is insufficient.  Aggregate root equality without
key/action/mass parity is also insufficient: compensating local errors are not a
receipt.

## 13. Mandatory malformed and semantic negative controls

The binding contract must give each control an exact error code and a zero-
accepted-result failure frame.  At minimum:

- force every key hash to one constant; full-byte net and final receipt stay
  identical;
- flip one actor byte in a public record; replay rejects it;
- inject a world ordinal or hidden-holder byte into an H key; schema/type
  validation rejects it;
- attempt to pass `M3WorldRevealedKeyV1` to an H grouping API; the typed API and
  a persisted malformed case reject it;
- delete one nonoptimal legal focal action; complete-face parity rejects it;
- skip the final forced one-tile focal frontier; census/key parity rejects it;
- alias roots 31 and 33 after their same-context projection; the root-alias KAT
  rejects it;
- duplicate or drop one particle/source ordinal; mass and source coverage reject
  it;
- mutate one terminal trick winner, count, loss transition or mass limb; exact
  parity rejects it;
- set each content cap to one below an observed requirement in a private control;
  the task fails with no partial result;
- corrupt, truncate, append to, reorder, or cross-bind a task checkpoint or final
  receipt; validation rejects the complete artifact; and
- substitute C bytes or values into an H task record; task typing rejects it even
  before numerical comparison.

Controls execute through memory-safe private inputs and cannot mutate the
production API's validated task.  A control failure is never retained as an M3
value.

## 14. Persistence, checkpoints and all-or-nothing completion

The exact M2 closure commit and its frozen CENSUS prefix are verified before any
current-path check.  The M3 identity graph is acyclic: rebrief bytes feed the M3
contract; contract bytes feed the freeze-57 descriptor; descriptor plus current
sources and immutable parent artifacts feed `M3SourceManifestV1`; SHA-256 of the
exact manifest bytes is `M3BuildIdentityV1`; and build, freeze and task semantic
digests feed the final receipt.  The contract contains none of its own digest or
any derived freeze, build, task, conjunction, receipt or final-commit digest.

Official builds and runs use an immutable exact-HEAD snapshot whose tree entries
and modes are checked against the producing commit, rather than a mutable live
worktree.  The source manifest is verified before and after both fresh runs.
Generated M3 receipts, checksums, checkpoints, diagnostics, AIR, targets and
caches remain outside the source manifest.

The full semantic digest covers every value-affecting or identity-affecting
input: freeze/build/manifest, task frame, support bytes and order, rules/table
identity, key codec, field law, valuation, loss automaton, arithmetic, ABI,
compiler/metallib, canonical order, caps, and receipt version.  A mismatch is
corruption for this artifact and the artifact is discarded whole; it is never
partially upgraded or treated as a compatible stale cache.

Raw GPU slots, partial epochs, incomplete local sorts, partial partitions,
partial reductions, incomplete faces and process-local `InfoStateId` maps are
nonpersistable.

During development, an atomic checkpoint may be written only after one complete
root/arm task has passed all of its CPU/GPU, mass, face, policy, control and
digest checks.  The checkpoint is a complete task artifact, written to a fresh
temporary path, fsynced as required by the binding contract, validated by an
independent parser, and atomically renamed.  Resume accepts it only under the
identical semantic and build identity.  A bad checkpoint discards the whole task;
no section is salvaged.

Official acceptance runs begin from fresh state with checkpoint loading and
checkpoint writing disabled.  They execute all eight tasks in canonical order
and emit one closed `M3PerfectRecallNetReceiptV1` only after every task and
control succeeds.  A second fresh official run must be byte-identical.  On any
failure the success receipt is absent; a typed diagnostic failure receipt may
name task, phase and progress counts but carries no partial values, policies,
nets, masses, or candidate success sentence.

## 17. Proposed official run order

The official runner performs this closed sequence:

1. verify the immutable freeze-55/freeze-56 prefix, manifests, contracts,
   receipts and exact parent identities;
2. verify `M3SourceManifestV1`, checked-in MSL/metallib identity, compiler profile,
   Cargo lock checksums, warning/no-float gates and source cleanliness;
3. run portable Rust tests, exhaustive legality/winner/count bridges, codec tests,
   the root-alias KAT and every malformed control not requiring Metal;
4. build the Lean target and run the axiom audit;
5. under elevated host access, verify the frozen Metal device/toolchain and run
   integer/ABI/transition kernel controls;
6. reconstruct and cross-check the receipt prefix, objective facts, void sets and
   complete 1,200-world support from fresh state;
7. run M3A roots 21, 31, 33, 55, comparing the independent H oracle, full GPU net
   and separately typed strict C control at each root;
8. run M3B roots 21, 31, 33, 55, comparing the independent pooled loss automaton,
   full GPU net and separately typed C computation at each root;
9. require cross-arm topology equality root by root, every receipt conjunct, every
   cap/guard check, and zero accepted partial tasks;
10. emit and independently validate the one closed binary receipt;
11. repeat steps 5--10 from fresh state with checkpoints disabled and require
    byte identity; and
12. reverify the source manifest after the run.

Only then may the frozen candidate sentence be emitted.  Exact values, policies,
counts, captures and timings may appear as typed receipt fields or noncanonical
appendices, but none broadens that sentence.

## 18. Stop rule

If any authority identity, carrier fact, full-key biconditional, support count,
action face, unique-parent reconstruction, exact mass, CPU/GPU value, policy,
strict C control, cap, guard, checkpoint, reproducibility run, Lean target, axiom
audit, compiler identity, or manifest check fails, M3 is not complete.

The implementation stops and reports the typed cause.  It does not sample,
decimate, omit a root, omit a forced frontier, increase a cap, weaken strictness,
substitute C for H, retain a partial fold, or transport a lower-grade observation
to trick 1.  Any necessary change to a frozen carrier, semantics, codec, ABI,
cap, receipt, or claim requires a new append-only adjudication.
