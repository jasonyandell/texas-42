# walt.wasm — the level-1 seat for the browser

walt as a WebAssembly decision oracle: bid, declare, and play decisions for
straight points-and-marks Texas 42, evaluated by the exact sampling-stack
solver (level-1 mind, exact rationals, no floats, no clocks in the value
path). **Exploratory tier** — sampled estimates, never receipts.

This directory is the whole handoff:

| file | what |
| --- | --- |
| `walt.wasm` | the solver (~250 KB, zero imports, no JS glue needed) — GENERATED by `../build.sh`, never hand-edited |
| `walt.ts` | typed wrapper: `Walt.load()`, `play()`, `bid()`, `declare()`, tile converters |
| `README.md` | this guide |

Verified by `../smoke.mjs`: a full hand driven through this exact binary
reproduces the native Rust test trace play-for-play (the solver is
deterministic per information state — same request, same bytes, native or
wasm, any platform).

## Quick start (plunge)

Copy `walt.wasm` + `walt.ts` into the client (e.g. `src/ai/walt/`). The
calls are synchronous and an opening lead can take seconds, so walt lives
in a **Web Worker** — never on the UI thread:

```ts
// src/ai/walt/worker.ts
import { Walt } from './walt';
import wasmUrl from './walt.wasm?url'; // vite: served as an asset

const walt = await Walt.load(fetch(wasmUrl));
self.onmessage = (e) => {
  const { id, kind, req } = e.data;
  try {
    const resp =
      kind === 'play' ? walt.play(req)
      : kind === 'bid' ? walt.bid(req)
      : walt.declare(req);
    self.postMessage({ id, resp });
  } catch (err) {
    self.postMessage({ id, error: String(err) });
  }
};
```

The main thread wraps that in a promise-per-request and gives the walt
difficulty an async path exactly like onyx's pre-warm: spawn the worker at
game start, fall back to `hard` if it isn't ready or the contract is out
of scope.

## Mapping plunge's `Observation` to walt requests

Seats are your own labels 0..3 (partners 0&2 vs 1&3) — walt rotates to its
internal frame itself. Tiles: walt uses triangular ids where
`id(high, low) = high*(high+1)/2 + low`; convert a `DominoId` like `"65"`
with `tileOf(6, 5)` and back with `pipsOf(id)`.

- `decl`: `{type:'pip', pip:p}` → `p` (0..6), `{type:'doubles'}` → `7`,
  `{type:'no-trump'}` → `9`.
- `bid`: `points` contract → its value (30..41); a **straight** `marks`
  contract → `42` (any marks level: the play target is all 42 points
  either way).
- `hand`: the seat's 7 **originally dealt** tiles — remaining hand plus
  its own tiles already in `tricks`/`currentTrick`.
- `plays`: the full chronological record as flat `(seat, tile)` pairs,
  rebuilt from `tricks` (in order) then `currentTrick`.
- `bidder`: the declarer (leads trick one).
- `seed`: pass something fixed per hand (e.g. derived from your game
  seed) so hands replay deterministically.

**Out of scope — fall back to `hard`** (the onyx pattern): nello, plunge,
splash, sevens, and any contract where the sat-out-partner rule is in
play. Walt is the straight-42 specialist.

### Auction

At the seat's turn: `bid({hand, need})` where `need` is current high + 1
(or 30). Response is `pass`, or `bid` with the walked-up level and the
declaration it leans on (not binding — declare for real after winning
with `declare({hand, bid})`). Calibration note: the default θ = 1/2 on
small samples is known to overbid on saturated hands; θ and `n` are
request parameters, and the tuned values will come out of the bidcurve
calibration corpus.

### Conformance assertion (do this)

Every `play` response carries walt's independently derived `leader` and
`points` (teams `[0&2, 1&3]`). Assert them against your engine on every
decision — two independent rules engines agreeing on every replay is the
cheap, permanent cross-check (this is exactly how the mk5 arena runs the
subprocess bridge).

## Tuning

- `n` (outer worlds, default 40): strength vs latency. `n0` (modeled mind
  sample, default 8). Cost scales roughly linearly in each; early-trick
  decisions dominate (opening ≈ seconds, late tricks ≈ milliseconds).
- `budgetMs` is inert in wasm (no monotonic clock): budget by `n`, and put
  a UI affordance on the wait instead ("walt is thinking").
- Threads: this build is the serial solver; a rayon/wasm-threads build
  (needs cross-origin isolation) is possible later if phones want it.

## Regenerating

`../build.sh` — rebuilds `walt.wasm` from the workspace source
(`rustup target add wasm32-unknown-unknown` once), re-runs the smoke
against the native trace, and refreshes this directory's binary.
