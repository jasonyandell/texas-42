## 4. Full net, exact recurrence and mass

At every S1 decision the net retains the complete legal set in ascending tile
index, emits every action, expands S0/S2/S3 chance plays until the next S1
decision or terminal, groups only complete byte-equal child keys, and retains
every edge mass.  The final one-tile S1 frontier is encoded, counted, sorted,
mass-checked and policy-checked.  A singleton fast path may avoid a comparison
but not the state or receipt.

A terminal field slot bypasses KEY-run construction and never receives a child
`InfoStateId` or H/C key.  After native completion, the host validates every
slot/status/guard, independently replays the terminal transition and retains it
as a terminal EDGE plus its exact objective bucket contribution.  It may seal
or publish neither record until every physical slab of that complete
parent/action emission has closed and the all-slab source-coverage, duplicate,
mass and transition checks have passed.  Terminal rows then enter the same
two-family schedule as the corresponding nonterminal evidence, under the
disjoint family rules below; there is no terminal information-state surrogate
and no slab-local terminal seal.

For a key `I`, complete legal face `L(I)`, root-scale terminal contribution
`T_I(a)`, and complete byte-equal children `J`, the only recurrence is

```text
A_I(a) = T_I(a) + sum_J V_J
V_I    = max_{a in L(I)} A_I(a).
```

There are exactly two semantic `REDUCE` families:

1. `MASS_BUCKET` executes after complete forward skeleton closure.  It
   partitions `EDGE_A` without omission or duplication.  Every nonterminal
   edge enters exactly one byte-equal child-key mass range.  Every terminal
   edge instead enters exactly one local `(parent,action,objective bucket)`
   range; it never also enters a child range.  Ranges remain action-local, so
   this family never globally sums the counterfactual mass copies created at a
   focal face.  Its outputs are mass/bucket evidence only and cannot supply an
   `A` or `V` operand.
2. `BACKWARD_VALUE` begins only after every `MASS_BUCKET` scratch source,
   destination and compaction run in the active H treatment or C microblock has
   closed, reparsed and been deleted.  Its level zero contains exactly one
   sealed `V_J` row for each distinct
   nonterminal child group, carrying the least canonical `EDGE_A` witness for
   that group, plus every terminal `EDGE_A` contribution directly.  A
   nonterminal group is represented once regardless of its arrival count.
   M3A's positive and negative magnitude lanes stably partition these rows
   (sign-zero rows enter the nonnegative lane); no row is copied between
   lanes.  M3B has the one nonnegative lane.  This family alone supplies the
   `A`, `V` and root recurrence.

Writing `E` for the complete purpose-7/`EDGE_A` census, `MASS_BUCKET` has
exactly `E` level-zero rows.  `BACKWARD_VALUE` has one row per nonterminal
child group plus one per terminal edge, hence at most `E` by the least-witness
injection.  Each family is therefore at most `2^26`, their aggregate
nonreplenishing level-zero census is at most `2E <= 2^27`, and there is no third
reduction family.  The two families and their scratch arenas never coexist.

Generic parent/action, epoch and root mass-conservation checks are independent
host folds over the complete raw CPU evidence and the complete post-Metal raw
evidence, or compare the already sealed `MASS_BUCKET` results; they never
launch another reduction.  After policy selection, terminal-bucket
conservation is checked again by two disjoint evidence-only folds, one over CPU
raw evidence and one over post-Metal host evidence.  Each fold visits every
selected-policy terminal edge exactly once and requires its bucket sum to equal
root mass.  These later buckets cannot feed `A`, `V`, the selected face or the
repricer and are not a `REDUCE` family.

All physical slabs and all particles for one child are summed before a maximum.
The full argmax face is retained; its least tile is a deterministic extracted
policy member only.  An independent no-maximization walk reprices that complete
fixed policy to the identical root value.  Child records strictly extend the
parent record.  Replay proves a unique parent key and focal action, including
zero-field successors, terminals and the root sentinel.  That theorem licenses
parent/action-local netting but never slab-local sealing.

contributions.  Every child carries the exact mass accumulated from its root

be derived for diagnostics after the recurrence but cannot enter a maximum or
receipt comparand.

Flags are bit 0 CLOSED, bit 1 SORTED and bit 2 MERGED_OR_REPLACEMENT; other bits
are zero.  Bit 2 names either an ordinary merge or the typed REDUCTION
compaction replacement below; record kind disambiguates them.
Width is 96/96/128/96/64/48/64/64/192/48 by kind.  Parent/action/emission are
exact for KEY_RUN files.  KEY_TABLE, STATE, ACTION, EDGE, both skeleton kinds
and REPRICE_VALUE use parent length zero, action/emission `u32/u64::MAX` and
zero parent bytes/digest.  Their run ordinal is their zero-based immutable
segment ordinal.  C_ROOT_FRONTIER has parent length zero, physical action equal
to the fixed root, emission ordinal zero and zero parent bytes/digest.  REDUCTION also
uses zero parent and action `u32::MAX`, but
its emission ordinal is the exact packed identity

```text
bits 0..7 dispatched reduction-pass ordinal 0..20; bits 8..15 focal epoch 0..3
bits 16..23 physical C block 0..74, or 255 for H
bits 24..31 family (1 MASS_BUCKET, 2 BACKWARD_VALUE); bits 32..63 zero
```

Together with the immutable run ordinal, this prevents header aliasing: files
inside one sequence may share the packed tuple but never its run ordinal, and
different family/block/epoch/level tuples never share the semantic identity.
Pass ordinals 21..255 are malformed; the admitted 21 values are exactly the
profile's maximum dispatched-level count.
Parent-key digest is
ordinary SHA-256 of exactly the declared parent-key prefix; it is all zero when
parent-key length is zero.  The assigned stream digest is the general
`W42M3DG1` construction over the complete raw record payload, using purpose
27/28/29/30/31/32/35/36/37/38 for kind
KEY_RUN/KEY_TABLE/STATE/ACTION/EDGE/REDUCTION/STATE_SKELETON/
ACTION_SKELETON/C_ROOT_FRONTIER/REPRICE_VALUE respectively, version one, the
header record count and payload byte count.  It is not a purpose-4/5 semantic
key digest because the spill record widths and fields differ.

For an original run `source-run count=0` and input-run-chain digest is all zero.
For a merged run or typed REDUCTION compaction replacement, source-run count is
positive and the input-run-chain digest is
purpose 34 over consecutive 40-byte records `(source run ordinal:u64,
source assigned-stream digest[32])` in the exact order consumed by the merge or
compaction.
The source list is unique, the count agrees with the header, and every named
closed source is independently reparsed before use.  The header self-digest is
ordinary SHA-256 of the 4,096 header bytes with offsets 312..343 zero.  A file
is readable only when CLOSED, its exact length is `4096+payload_bytes`, all
reserved bytes are zero, and both payload digests and any input-run chain
reproduce.  Files contain one record kind only.  Cross-file offsets are u64.
Run inputs are deleted only after the replacement merged run is closed, fsynced,
reparsed and digested.  Spill is noncanonical scratch and never accepted as a
checkpoint or receipt.

KEY_RUN files are transient and confined to one complete parent/action
emission.  Their complete merge groups every repeated arrival by full bytes;
the proved unique-parent/action property says no sealed child key can appear in
another emission.  Each sealed group is appended once in deterministic
discovery order `(focal epoch, parent InfoStateId or u32::MAX for the root,
physical action, child-key bytes)` to KEY_TABLE segments of at most `2^19`
rows.  `InfoStateId` and global key-table ordinal both equal discovery ordinal.
An active segment lives in the separately charged 96-byte table-builder slab;
it closes immutably when full, at H treatment end or at C block end, so H has at most sixteen
segments.  C uses one shared builder in encoded-world/discovery order within a
microblock; a segment may cross a world boundary but its full keys remain
world-tagged and are never grouped across that boundary.  The
32-byte resident/state index is ID-indexed metadata, never a hash-equality
authority.  A later all-key full-byte sort rejects any cross-emission duplicate
before acceptance, which executable replay and Lean unique parent prove
impossible.  Discovery order remains scratch identity, not
`CanonicalStateOrdinalV1`.

The canonicalization copy sorts complete KEY_TABLE rows by `(key byte slice
lexicographically, InfoStateId)`; a shorter slice sorts first only when it is a
prefix, and padding is ignored.  Comparison uses length-delimited full bytes,
never a hash.  Two equal key byte strings are a
failure regardless of IDs.  H rank in this unique copy is
`CanonicalStateOrdinalV1`; C performs the same sort per world and adds the
checked prior encoded-world prefix count.  The resulting ID-to-canonical-rank
map occupies the already charged 32-byte/state metadata and is independently
replayed before any semantic ordinal is serialized.

Forward construction never writes placeholder final STATE or ACTION values.
At key sealing it appends the immutable KEY_TABLE and STATE_SKELETON rows.  Once
a complete parent/action emission seals, it appends parent-canonical EDGE_A rows
and one ACTION_SKELETON.  The latter stores purpose 27 over the final canonical
nonterminal KEY_RUN payload (the exact zero-record purpose-27 digest when the
action is terminal-only).  Those rows and headers are flushed before KEY_RUN
deletion; a crash discards all scratch.  At skeleton-segment or epoch closure an
independent join reconstructs the same key payload from EDGE_A
`(source,scoped-arrival,child InfoStateId)` plus KEY_TABLE, verifies the stored
digest/count/range and the STATE/KEY_TABLE bijection, then reparses the closed
files.  This bounded transaction leaves neither dangling arrival evidence nor
millions of retained 4-KiB KEY_RUN headers.  The root sentinel uses an identical
fixed ACTION_SKELETON-form descriptor with parent `u32::MAX`, the fixed root,
global skeleton-record ordinal `u64::MAX`, its EDGE_A first/count, terminal flag
as observed and the purpose-27 lineage digest; no ordinary action uses either
sentinel.

After the complete forward STATE_SKELETON, ACTION_SKELETON and EDGE_A evidence
for the active H treatment or C microblock has closed, `MASS_BUCKET` alone
renders and CPU/Metal-compares the final MASS and local terminal-bucket
evidence.  It replaces no skeleton.  Every one of its source, destination and
compaction runs is deleted after closure/reparse before backward processing
starts.

`BACKWARD_VALUE` then processes reverse epochs and consumes only closed
STATE_SKELETON, ACTION_SKELETON, EDGE_A, terminal descriptors and already
sealed child `V_J` rows.  It emits immutable final ACTION and STATE segments in
the same global skeleton-record order, verifies their one-to-one ranges/values,
closes and reparses them, and only then deletes the matching old skeleton
segment.  Final ACTION values and mass therefore never masquerade as
forward-known fields.  At most one `2^19`-row segment of each skeleton kind
overlaps its final replacement.  Fixed-policy repricing is later evidence and
never rewrites either final kind.

EDGE_A is retained permanently in discovery parent/action/source/arrival order;
ACTION_SKELETON and final ACTION ranges point only into A.  Before KEY_RUN
deletion every nonterminal A row is bijected to its scoped KEY_RUN arrival;
terminals use the terminal grammar of section 4.  Sequential external sorts use
only one complete 64-byte edge copy at a time.  EDGE_CHILD_B orders nonterminals
by `(child full key,source,scoped arrival,parent,action,global edge ordinal)`;
from B plus KEY_TABLE the gate streams purpose 4/5 arrival records, rejects
duplicates, reproduces the ranks assigned by the separate full KEY_TABLE sort
and deletes B.  EDGE_SEMANTIC_C then
orders mapped rows for purpose 7 and grouped topology, is byte-compared between
CPU and Metal, and is deleted; B and C never coexist.  Global edge/scoped
arrival u32 values are zero-extended into the purpose-7 u64 arrival field.

H purpose-7 order is root sentinel first, then canonical parent, action,
terminal flag, child, source and arrival.  C purpose-7 order is world-major in
the frozen encoded-world order: that world's root-sentinel edges first, then
its non-sentinel canonical parent/action/terminal/child/source/arrival rows.
Purpose 7 is a within-treatment CPU/Metal comparand; objective-projected purpose
17 remains the cross-objective authority.  For C topology, the retained root
frontier first streams the single sentinel STATE and all root projected EDGEs
in complete child-key order; the main blocks then stream only non-sentinel
records.  No all-C edge spool is implied.

Reduction records follow the exact H/C outer scheduler order above; within one

unchanged U256 and lineage,
and assigns the new dense level-local row ordinal.  It never changes the row

equality, dense ordinals, digests and closure; only then may the old run be

## 6. Shared ABI, Metal kernels and exact live bytes

The official target/toolchain is the freeze-56 target: little-endian
`aarch64-apple-darwin`, Rust 1.95.0 release with overflow checks and Cargo
`--locked`, Xcode 26.6 build 17F113, Metal component 32023.883, SDK 26.5,
deployment target 26.0.  The exact M3 shader sources, in order, are
`00_u256.metal` and `02_m3_wavefront.metal`.  Each is compiled separately with

```text
-std=metal3.2 -mmacosx-version-min=26.0 -fmetal-math-mode=safe
-fno-fast-math -Wall -Wextra -Werror -c <SOURCE> -o <AIR>
```

and linked in that order.  Two fresh-directory libraries and checked-in
`walt-metal/shaders/walt_m3.metallib` must be byte-identical; the freeze
descriptor and source manifest bind the final digest.  AIR and paths are not
canonical.  Environment sanitization and tool executable/version/digest records
are exactly as freeze 56.  No new unsafe operation class is admitted: only
checked host-word copy to shared buffer, completed shared-buffer copy to owned
words, and validated buffer/offset-zero encoder binding remain allowed.

Every shared ABI struct is private `repr(C)` containing only `words:[u32;N]`;
compile-time size/alignment assertions are mandatory.  Hashing appends each
word's `to_le_bytes` and never hashes padding or struct memory.  Poison is
`0xA5A55A5A`; invalid tile is `0xffffffff`.

Focal application is an explicit host responsibility, closing rather than
hiding the Metal boundary.  For every sealed S1 key and every legal action, the
host iterates its particles in source order, verifies actor/key/hand/legal face,
copies the exact mass and exponent without division, removes that tile from S1,
appends `(S1,action)` to the complete record, and, if it is the fourth play,
applies frozen winner/count and objective transition before constructing the
next particle.  A disjoint replay implementation regenerates the entire output
stream from the parent key and frozen game rules and must match byte-for-byte.
The stream, complete action census and mass-copy digest enter treatment parity.
No oracle grouping/value/policy code is shared.  Metal then performs every
non-focal legal generation, mass multiplication, hand/state transition and
trick resolution.  This host copy-on-write grammar is the only focal fast path;
it cannot skip the final singleton frontier or be represented as chance.

`M3KernelControlV1` is 64 bytes/16 words:

```text
0 ABI=1; 1 opcode (1 EXPAND, 2 REDUCE); 2 command ordinal; 3 task ordinal
4 objective; 5 treatment; 6 input/plan count; 7 field exponent before command
  (EXPAND) or global source-row base (REDUCE)
8 logical output count; 9 physical root index (EXPAND) or global
  destination-row base (REDUCE); 10 reduction level
11 reduction source count; 12 reduction destination count
13 reduction range count; 14 flags=0; 15 reserved=0
```

Opcode-inapplicable fields are zero.  EXPAND requires words 10..13 zero.
REDUCE requires word 6 (plan count), word 8 (logical output count) and word 12
(destination count) equal.  Word 11 is the exact local source count and every
referenced left/right index is below it; every source except an unpaired final
carry is referenced exactly once in canonical adjacency.  REDUCE uses words 7 and 9 as the checked
u32 bases of this command's consecutive slice in the complete current and
next-level logical row streams; physical root is thereby inapplicable and not
present in a reduction control.  Base-plus-count is checked without wrap before
dispatch.  Before dispatch, the immutable command manifest maps word 2 to its
exact ordered slice or slices of REDUCTION headers, checks every packed
family/block/epoch/level identity and checks word 10 against their common
level; this schedule binding adds no ABI field.
This opcode-specific interpretation is part of ABI version one.

`M3ParticleAbiV1` is 96 bytes/24 words:

```text
0 ABI=1; 1 status=1 VALID; 2 task ordinal; 3 support source ordinal
4..7 hands S0..S3 low-28-bit masks
8 packed state; 9 four 5-bit current-trick tiles (31 means empty)
10 future T0 spend; 11 host record ordinal
12..19 U256 mass; 20..23 reserved zero
```

Packed state bits are leader 0..1, next actor 2..3, trick length 4..6,
completed-future-tricks 7..9, future-T1-wins 10..12, field exponent 13..16,
complete-record length 17..21; bits 22..31 are zero.  Every field is replayed.
If trick length is `k`, word-9 lanes `0..k-1` contain distinct tile indices
`0..27` in chronological order and lanes `k..3` are exactly sentinel 31;
bits 20..31 are zero.  Empty lanes containing zero, live lanes containing 31,
duplicate live tiles or a lane pattern inconsistent with packed `k` are
malformed even if replay would otherwise fail later.

`M3FieldSlotAbiV1` is 112 bytes/28 words:

```text
0 ABI=1; 1 status (0 EMPTY,1 VALID,2 HARD); 2 error code
3 parent input ordinal; 4 fixed slot ordinal 0..6; 5 legal degree 1..7
6 selected tile or 0xffffffff; 7 task ordinal; 8 support source ordinal
9..12 hands S0..S3; 13 packed state; 14 packed current trick
15 future T0 spend; 16 host-child ordinal=0; 17..24 U256 mass
25 packed completed winner/count (winner 0..3 or 4 none; points 0..31)
26 transition flags; 27 reserved=0
```

In word 14, trick tile `j` occupies bits `5*j..5*j+4`; bits 20..31 are
zero.  For VALID, its live/empty lanes obey the same distinct-`0..27`/sentinel-31
rule as Particle word 9 using output packed trick length.  In word 25 winner occupies bits 0..2 and exact trick points occupy bits
3..7; bits 8..31 are zero.  Winner 4 is permitted only with points zero and
means no trick completed.  Word-26 flag bits are 0 trick completed, 1 terminal,
2 next actor is S1 and 3 objective already decided; bits 4..31 are zero.
Objective-decided is diagnostic only and never prunes.  The exact point range is
0..31 because `1 + 10 + 10 + 5 + 5` is attainable; any narrower field would be
an invalid P30 ABI.

Canonical EMPTY is word-for-word: word 0 is 1, word 1 is 0, word 2 is 0,
words 3/4/5 are parent/slot/legal-degree, word 6 is `0xffffffff`, words 7/8 are
task/source and words 9..27 are zero.  Canonical HARD is word-for-word: word 0
is 1, word 1 is 2, word 2 is the first error, words 3/4 are parent/slot, word 5
is zero, word 6 is `0xffffffff`, words 7/8 are task/source and words 9..27 are
zero.  A hard thread rewrites all seven owned slots to that form with the same
error, parent, task and source and each slot's own ordinal.  Error
precedence/codes are: 1 BAD_ABI,
2 BAD_TASK, 3 BAD_OBJECTIVE, 4 BAD_TREATMENT, 5 BAD_MASK, 6 BAD_PACKED_STATE,
7 BAD_ACTOR, 8 BAD_LEGAL_DEGREE, 9 BAD_TILE, 10 REPEATED_TILE,
11 MASS_OVERFLOW, 12 BAD_EXPONENT, 13 TRICK_RESOLUTION, 14 LOSS_RANGE,
15 SLOT_RANGE, 16 INTERNAL.  Unknown/noncanonical forms reject the command.

For EMPTY, VALID and HARD alike, parent is exactly input word 11 (the host
record ordinal), task is exactly control word 3 and source is exactly input word
3.  The kernel snapshots those three provenance words before validation, so
even BAD_TASK and later HARD forms are unique; slot is the owned `j=0..6` and
EMPTY legal degree is the independently computed input legal degree.

`M3ReductionAbiV1` is 48 bytes/twelve words: word 0 ABI=1, word 1 status
(1 VALID, 2 HARD), word 2 error, word 3 canonical row ordinal and words 4..11
the U256 limbs.  VALID has error zero.  HARD preserves ABI, status, first error
and row ordinal and zeros every limb.  Reduction errors in precedence are
1 BAD_ABI, 2 BAD_STATUS, 3 BAD_ROW_ORDINAL, 4 BAD_PLAN_INDEX,
5 BAD_CARRY_FORM, 6 ADD_OVERFLOW and 7 INTERNAL.  A bare U256 is never a
reduction destination, so native command completion cannot hide arithmetic
wrap.  `M3ReductionPairV1` is 16 bytes: left source index, right source index or
`u32::MAX` for carry, destination index, flags (bit 0 carry, all other bits
zero).  Pair indices address logical records after the leading guard.  Before
dispatch the checked-plan type proves in-range sources/destinations, unique
destinations, canonical adjacency and no cross-range pair; malformed plans are
rejected without dispatch.  The kernel independently validates every property
that is safe to validate per thread and emits HARD on source/status/add errors.

Pair-plan `left/right/destination` are zero-based logical indices.  Reduction
thread `gid` reads `plan[gid+1]`, reads `source[1+left]` and, unless carry,
`source[1+right]`, and is the sole writer of `destination[1+destination]`.
The indices are local to this command, but row identity is global: the kernel
requires each read row's word 3 to equal checked
`control.source_row_base + local_source_index` and writes destination word 3 as
checked `control.destination_row_base + plan.destination` for both add and
carry.  Plan destinations are exactly `0..destination_count-1`; the two bases
are the canonical prefixes reconstructed from all preceding ranges and command
chunks.  The host may not rewrite a GPU-emitted row ordinal after completion.
Index zero and index `capacity+1` of all three arenas are poison guards.
The dispatch grid equals control plan count; rows beyond the logical
source/plan/destination counts through the trailing guards remain poison.
Creating the separately typed next-active-level compaction run described in
section 5 is not an ordinal rewrite: it is a new immutable record population
with a new immutable run ordinal under the same semantic packed emission
identity and an independently checked bijection to the completed GPU output.

Buffers bind at offset zero.  Record zero and the final record are guards;
logical input is `inputs[gid+1]`, owned outputs are
`outputs[1+7*gid+j]`.  A field thread first writes all seven canonical EMPTY
records, enumerates legal tiles ascending, then writes VALID slots.  One thread
owns every written word.  It performs legality, hand removal, transition,
winner/count/loss updates and `U256` multiplication.  No atomics or concurrent
command buffers are allowed.

Reduction inputs are already in the canonical order assigned to exactly one of
the two semantic families.  `MASS_BUCKET` orders nonterminal child-key mass
ranges by complete child key/source/arrival and local terminal-bucket ranges by
parent/action/objective bucket/source/arrival.  `BACKWARD_VALUE` orders sealed
nonterminal `V_J` rows and direct terminal rows by
owner/action/source/arrival/least-witness identity; its root sentinel is an
ordinary range in the same family.  For every semantic range, level zero pairs
adjacent rows, carries an odd last row, and concatenates ranges in range order.
Count-one ranges seal without dispatch.  Later active levels repeat until one
row remains per range, using the immutable dense compaction protocol of
section 5.  The complete checked pair plan is built independently by the host;
no pair crosses a range.  One command may pack consecutive complete pair/carry
units from several ranges and, for C, from several worlds only inside the same
declared microblock.  Every range remains world-local, no pair crosses a world,
and no command crosses family, block, focal epoch or level.  Every pass is a
separate committed/completed command,
alternates the two arenas, overwrites exactly its destination prefix and leaves
tail/guards poisoned.  Sums visit left then right with limb order 0..7.  A
maximum cannot precede the final `BACKWARD_VALUE` pass.

If one family/block/epoch reduction level has more than 524,288 source rows,
its canonical adjacent pairs are divided into consecutive commands only
between pairs.  Each
command's completed outputs are appended in plan order to a closed next-level
run; the next level starts only after all such runs are merged and checked.
Every H range is bounded by the complete root-to-first emission count
2,073,600, and every C range is world-local and bounded by 1,327,104.  A
child-key or local terminal-bucket range in `MASS_BUCKET`, or an action/root
range in `BACKWARD_VALUE`, may exceed `2^19` and then continues across
consecutive commands.  A boundary occurs only between canonical adjacent
pairs, every output retains the same reconstructed family and range identity,
and all partial outputs enter the next complete level before singleton
retirement and compaction.  Sealing, maximum and subtraction wait until the
range has exactly one row.  This is the same reduction tree as one unbounded
pass and changes neither order nor grouping.

M3A never feeds signed integers to the U256 adder.  In `BACKWARD_VALUE`, signed
child and terminal rows are stably partitioned into positive- and
negative-magnitude lanes in original canonical order, with a sign-zero row in
the nonnegative lane.  Each level-zero row enters exactly one lane.  Each lane
is reduced completely as U256, then the two magnitudes are compared and the
smaller is checked-subtracted from the larger to obtain sign/magnitude.  Zero
has sign zero.  M3B `BACKWARD_VALUE` and every `MASS_BUCKET` range use the one
nonnegative lane.

Both kernels use `dispatchThreads`, threadgroup `(32,1,1)`, exact logical grid,
and no rounded thread.  Maximum pipeline threads must be at least 32.  Native
completion with no error is required before any read.  Input/control/plan
pre/post hashes must match; every destination logical record is overwritten;
every tail and guard remains poison.

## 8. Child protocol and liveness

The child writes only complete little-endian frames:

```text
u32 payload_length = 28 + detail_length
u16 protocol=1; u16 kind
u32 phase; u32 task ordinal; u32 treatment; u32 command ordinal

```

The complete frame is `32+detail_length`; payload length is at most
`0x7fffffff`.  Kinds are 1 TASK_BEGIN, 2 PREPARING, 3 COMMITTED, 4 TERMINAL,
5 TASK_SUCCESS, 6 FINALIZING, 7 SUCCESS, 8 FAILURE.  Progress details for kinds
1--4 are empty.  `TASK_SUCCESS` detail is one 512-byte
`CompleteTaskEvidenceV1`; SUCCESS detail is one 52,880-byte success receipt and
FAILURE detail is one 512-byte failure receipt.  FINALIZING detail is empty.
Terminal codes are 1 COMPLETED, 2 ERROR, 3 TIMEOUT,
4 NOT_ENQUEUED, 5 NOT_COMMITTED, 6 SCHEDULED and 7 UNKNOWN.  Only COMPLETED
with no native error can validate buffers.  Command ordinals are contiguous
across both treatments and task-owned controls within one objective task; the
global-control namespace separately starts at zero.  `u32::MAX`
denotes a nonapplicable task/treatment/command and no other sentinel is valid.

Code and context fields are closed by kind.  TASK_BEGIN has phase 4, its task,
treatment/command unavailable and code zero.  PREPARING uses the exact DFA
phase/context, command unavailable and code zero.  COMMITTED uses code
SCHEDULED; TERMINAL uses only COMPLETED, ERROR or TIMEOUT, with the identical
phase/task/treatment/command as its COMMITTED.  TASK_SUCCESS has phase 12, its
task, treatment/command unavailable and code COMPLETED.  This phase value also
applies when the task owns zero controls and therefore has no local phase-12
PREPARING marker.  FINALIZING has phase 14 and SUCCESS phase 15; both have all
three context ordinals unavailable, with codes zero and COMPLETED respectively.
FAILURE names the phase and most specific available context, its code equals
the embedded `M3FailureReceiptV1.code`, and its native-status detail uses
NOT_ENQUEUED, NOT_COMMITTED or UNKNOWN when no TERMINAL exists.  Any other
kind/code/context combination is malformed.

For FAILURE, task is present exactly while an objective task is active,
treatment exactly while an H/C treatment is active, and command is the named
candidate ordinal for NOT_ENQUEUED/NOT_COMMITTED or the committed ordinal
through the immediately following FAILURE when its TERMINAL is non-COMPLETED;
otherwise each field is unavailable.  If a TERMINAL preceded FAILURE, native
status repeats ERROR or TIMEOUT; before enqueue it is NOT_ENQUEUED, after
enqueue but before commit it is NOT_COMMITTED, and every other no-TERMINAL
failure uses UNKNOWN.
