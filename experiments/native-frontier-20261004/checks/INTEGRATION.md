# Independent pinned-source integration requirements

2026-10-04. Scope: source inspection at canonical checkpoint 490997b13b161099dcfbcf19f2dec0819fd5a019; native integer-array batch experiment only. No higher-k complexity or playing-strength claim.

1. **Frozen randomness differs from the Python prototype.** Native `solver/mod.rs::solve_field_dice` uses ascending legal bits, selects `SplitMix64(seed[sid] ^ record_hash(key)).below(legal_count)`, then discards that local stream. `below` uses rejection at `zone = u64::MAX - u64::MAX % n` and accepted-value modulo. This is not multiply-high tape selection, not a mutable RNG advanced along a branch, and not an explicit depth-indexed uniform array. For a singleton move it consumes no draw. Exact finite native semantics require that RNG including rejection and wrapping arithmetic.
2. **Inner worlds are actor-specific.** `pi(k,key,seat,hand,legal_mask)` constructs belief from that actor's remaining hand, full represented Key and boundary capacities. Its seed is `INNER_SEED ^ level_tag ^ mix(seat) ^ mix(hand) ^ record_hash(key)` where the zero level tag is zero and higher tags are `mix(0x4C32 ^ k)`. The default is Voidless: a single mutable unseen tile vector is Fisher-Yates shuffled successively, not reset between sampled worlds. After all worlds, Dice seeds are consecutive RNG outputs. Counted beliefs have a different kernel stream and public void state. Preserve duplicate sample multiplicity.
3. **Cache identity is more than record_hash.** PolicyKey equality uses actor, hand, played, leader, unfinished ordered trick (with length), both banked totals, represented optional voids and rung. Shared evaluation scope additionally fixes declaration, contract/bid, n_inner budgets, normalized or exact boundary, inner belief strategy and modeled selection rule. `record_hash` intentionally omits scores/voids; it is a seed coordinate, never complete cache equality. Host scenario ID and outer support membership must not affect modeled policy identity.
4. **Full-history focal decisions.** Each batch query must have its own root identity. Intern `(parent-history-ID, played tile)` without truncation, across each full continuation. MAX/MIN is taken after aggregation of every retained scenario reaching the same complete focal history. Nonfocal deterministic branches partition sample mass and sum. A maximizer seeks T1 success and a minimizer seeks T1 failure; focal-success conversion is only a reporting convention. A compressed native public state can be a valid future-value memo coordinate for the pinned state-based field, but a full-history frontier must not accidentally merge branches merely because their played set/current trick coincide.
5. **Actions and ties.** Legal actions are ascending tile IDs. Fixed choice uses strict improvement, retaining the smallest ID on ties. Interior viewer capture-first ordering is value-only, with optional exact saturation break; no exposed tie follows from it. Field bucket order is ascending played tile. Exact integer success counts preserve duplicates and are normalized only at the public rational boundary.
6. **Rules/settlement.** Straight terminal make is `banked_t1 >= bid`; set is `banked_t0 > 42-bid`. Winner is first strict maximum, and trick count is one plus tile count totals. Boundary capacities subtract completed full tricks and then unfinished trick actors. Eligibility guards should explicitly refuse unsupported contracts/declarations/configurations and malformed input rather than silently approximate. Historical support replay must run the complete supplied prefix without stopping at a contract threshold.
7. **Budget/refusal.** Only complete successful policy answers may enter a cache. A batch refusal must propagate; zero-filled or truncated arrays cannot be interpreted as results. Charge queue creation, actor-specific sampling, forward materialization, sorting/history interning, backward reduction, cache lookup, serialization, and fallback/refusal work separately and end-to-end. Peak array bytes and process RSS are different measures.
