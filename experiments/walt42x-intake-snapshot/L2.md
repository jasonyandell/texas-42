# Repaired NumPy Walt L2

2026-09-29. Exploratory implementation; floats are accepted for this work.
The repaired ladder is in `repaired.py`, with small Numba kernels in
`nested_kernels.py`. The original pasted source and the earlier throughput
implementation remain available as reference artifacts.

## Level names and scope

| New name | Policy | Pasted script name |
|---|---|---|
| L0 | Uniform random legal play | `random_policy` |
| L1 | Best response to L0 | Table `level=0` |
| L2 | Best response to L1 at each other seat | Table `level=1` |

The measured L2 configuration has **30 outer deals and 8 inner L1 deals**,
delta=1, seed schedule 42, and all four table seats using L2. The other three
seats in each search, including the partner, are modeled as L1. Contract/rules
scope remains the pasted bid-30, seats-1/3-declaring, seven pip-trump game.
This is not the production Walt's full declaration/contract surface.

`--samples 8,30` lists the sample schedule **bottom rung first**. Changing
sample counts creates a different finite-sample policy, not a free speedup.
Delta=0 integrates the random legal field at L1; positive delta retains the
threshold sampling mechanism. The full-game measurements below use delta=1.
No full-opening delta=0 L2 performance or playing-strength claim is made.

## Repairs

1. **Public information survives every outer transition.** Public states carry
   all actor-attributed plays, stored losslessly as four uint64 words, and four
   accumulated void masks. Failure to follow updates the acting seat's voids.
   Modeled samples use both the root constraints and all subsequent observations.
2. **The field is a function of the acting seat's information.** Its input is
   that seat's remaining hand, the complete public state/history, and immutable
   model configuration. No other hidden hand or enclosing deal ID is accepted.
   A BLAKE2-derived state seed initializes a separate RNG. Query ordering,
   worker scheduling, batch size, cache hits and parent-search RNG consumption
   cannot change a completed modeled action.
3. **Field identities are canonical and level-specific.** `1` and `1.0` for
   delta are identical settings. Sample schedules become immutable tuples.
   An L1 field's identity contains its own schedule prefix, not an enclosing
   L2 solver's sample budget. The current policy version is `walt42x-pure-v2`.
4. **Full keys guard cache identity.** Hashes seed RNGs but do not identify cache
   entries. Cache equality compares level, own hand and all public-key fields.
   Entries are immutable; the exposed cache view and field spec cannot be
   replaced through their public interfaces. The cache retains at most 50,000
   entries. Uncached queries recompute the same pure function.
5. **Sampling terminates without rejection.** Integer capacity DP counts all
   allocations consistent with the remaining capacities and public voids.
   Uniform ranks are independently drawn with replacement and unranked into
   deals. Impossible information states fail explicitly. This preserves the
   intended *uniform public-void support* distribution; it does not introduce
   Bayesian likelihood weighting for the assumed policies' past actions.
6. **Incomplete work never masquerades as L2.** Terminal roots are rejected
   explicitly. Time/frontier exhaustion produces an `incomplete` receipt with
   the reason and completed move prefix; there is no lower-rung substitution
   or arbitrary action fallback. A large batch can be bisected and retried with
   identical state seeds, preserving every sample count and decision target.

## Throughput engineering

Duplicate information-state queries are grouped before solving. Independent
L1 roots share a NumPy frontier batch while retaining separate focal seats,
deal sets, root ownership and RNG streams. Deal sampling is also batched in
compiled loops. Uniform-field edge emission reuses the earlier sparse compiled
kernel; no Rust rewrite or GPU is needed.

Forced decisions return their sole legal tile without searching. Because RNG
streams are state-local, skipping these computations cannot shift later samples.
Inside an L1 search, L0 is memoryless uniform legal play, so complete history
and void records need not be copied through every internal node after root
sampling. They remain present throughout the L2 frontier where modeled L1
queries actually need them.

A profile caught an accidental repeated calculation of a whole batch's turn
array for each result; computing it once removed several seconds from the
opening-heavy hand. Most field queries are genuinely distinct: memoization alone
cannot eliminate this ladder's cost. The measured seed-1 game evaluates 263,997
unique L1 misses and about 93 million L1 fiber visits.

## Measurements

Apple M5 Max, CPU execution, Python 3.12 / NumPy 2.4.4 / Numba 0.65.1.
Eight seeds (1–8), batch size 256, four spawned workers, fresh field/cache per
game, full play until contract settlement. Time includes dealing, sampling,
all levels of solving and move execution. Panel wall time additionally includes
worker startup and incremental JSON receipt writing. It is one descriptive panel,
not a strength study or a statistically established timing distribution.

For **30 outer / 8 inner, delta=1**:

- All **8/8 games completed**, with no fallback or deadline/frontier failure.
- Median per-game time: **9.61 s**; observed range **3.30–14.49 s**.
- Median first-decision time: **6.34 s**; range **1.68–9.71 s**.
- Whole panel: **21.09 s**, or **0.379 games/s / 22.8 games/minute** on four workers.
- The earlier single-process seed-1 run took 14.61 s before the redundant-turn
  calculation was removed. That pre-optimization receipt remains available.

L2 is now usable for offline computation at this sample budget. The opening
latency still takes seconds; batching independent games improves throughput,
not the latency of an individual decision.

The separately labeled **8 outer / 4 inner, delta=1** panel also completed
**8/8 games**. Median game time was **1.90 s**, range **0.65–2.90 s**; median
first-decision time was **1.23 s**. Four workers finished it in **4.40 s**,
or **1.817 games/s / 109 games/minute**, including worker startup. These are
different sampled policies, so this is a budget/latency comparison, not a claim
that the smaller configuration preserves playing strength.

A complete seed-1 30/8 game with caching disabled and batch size 64 took
11.19 s and followed the same plays as the cached batch-256 run. The sampler,
field identity and chosen policy therefore do not depend on those execution
choices in this full-game witness.

The unversioned `repaired-l2-initial.json`, `repaired-l2-b128.json` and
`repaired-l2-b512.json` are prototype receipts, not v2 measurements. Prototype
field IDs distinguished integer `1` from floating `1.0`, so those runs must not
be treated as a same-policy batch-size comparison with each other or with v2.

## Verification

`verify_repaired.py` provides executable evidence for:

- 48 L1/L2 endgame comparisons with an independent scalar recursive policy
  implementation, using the original NumPy search as its solve reference.
- Independent rational-arithmetic values for selected exact L1 endgames.
- Public transitions, actor attribution, score and void updates checked against
  a separate scalar referee on 120 reachable positions, plus a complete 28-play
  history exercising all four packed-history words.
- Uniform support ranking checked exhaustively on 80 small physical states,
  all 343 three-tile allowed-seat-mask patterns, and the known opening support
  count `21! / (7!)^3 = 399,072,960`.
- Duplicate-state, reordered-batch, mixed-actor, cache/no-cache and full-opening
  batch invariance, plus unchanged L1 seeding when only the L2 sample count changes.
- Capacity-triggered batch splitting preserving complete values, immutable
  exposed cache/spec, inconsistent-support refusal, terminal handling and deadlines.

`verify_l2_runs.py` independently referees each recorded physical game, checks
root action sets and selected actions against returned values, and compares
complete traces between receipts with the same policy configuration.

These are bounded tests. Float64 values and sampled worlds remain numerical
and statistical approximations where applicable; the measurements do not claim
exact values over all possible hidden deals or superior real playing strength.

## Run

The measured interpreter is
`/Users/jason/.local/share/mise/installs/python/3.12/bin/python3`.
Use a Python with NumPy and Numba installed; the verification scripts also use
the earlier intake's test helpers, which import PyTorch.

```sh
cd experiments/walt42x-intake
python3 verify_repaired.py
python3 l2_bench.py --samples 8,30 --level 2 --delta 1 --batch 256 \
  --games 8 --workers 4 --seconds 120 --output results/my-l2.json
python3 verify_l2_runs.py results/my-l2.json
```

For a single game, use `--games 1 --workers 1`. For a smaller computational
policy, use `--samples 4,8` (8 outer / 4 inner). The budget is explicit in every
receipt and never reduced automatically. `--no-cache` is useful for purity
verification. `--seconds` is a cooperative per-game deadline checked between
bounded operations; it is not an OS hard kill. A per-search frontier guard
prevents uncontrolled expansion; retained earlier plies mean it is not an
absolute process-memory ceiling.
